## 一、 为什么要做这个？（痛点与产品初衷）

自打 Cursor、Claude、Antigravity 等 AI 编程工具成为日常主力后，我发现每天写代码有大量时间在做一件极其枯燥的事：
1. **频繁切窗**：在编辑器看代码 ➔ 拍键盘 `Alt+Tab` 切到 AI 窗口；
2. **点鼠标对准**：鼠标点击输入框；
3. **输入提问**：键盘噼里啪啦敲一段几十个字的 Prompt；
4. **敲回车发送**：敲 Enter，然后再 `Alt+Tab` 切回代码看效果。

**一天下来切窗几百次，极其打断专注心流！**  
市面上很多纯软件语音助手，要么需要全局软件热键注入（很容易跟各类 IDE 快捷键冲突），要么在企业微信、千牛后台等敏感场景容易被平台判定为“外挂注入”封号。

**我们的目标只有一个**：  
做一款摆在桌面上、巴掌大小、带全彩屏幕和独立芯片的**物理实体呼叫台**。想跟 AI 提需求时，甚至不用碰键盘鼠标，随手一点就能从容表达，说完自动敲回车发给 AI！

## 二、 硬件选型：为什么买 300 多近 400 块的 M5Stack CoreS3？

很多人问：*“现在树莓派 Pico RP2040 只要 15~20 块钱，ESP32 裸板只要十几块，为什么偏偏选接近 400 块的 M5Stack CoreS3？”*

### 核心选型考量：
1. **全集成的精致手感**：
   - CoreS3 搭载了 ESP32-S3 双核 240MHz 芯片 + 16MB Flash + 8MB PSRAM；
   - 自带 2.0 寸电容触摸屏（320×240 分辨率），出厂带一体化磨砂外壳与磁吸底座；
   - 内置双高保真麦克风阵列与 16-bit I2S 功放扬声器；
2. **免外壳 3D 打印与飞线折腾**：
   - 便宜的裸板自己打外壳、焊屏幕、接麦克风，算上工时和报废率成本反而更高；
   - CoreS3 摆在桌上就是一件精致的赛博科技好物，可以直接作为成熟商品交付。
3. **物理 HID 免驱防封**：
   - 芯片硬件底层原生支持 USB CDC + USB HID 键鼠报文；
   - 操作系统识别它是一个真正的物理外部键盘，零软件钩子注入，从物理根源上彻底免疫平台封号反作弊！

## 三、 深度复盘：我们一路踩平的 7 大“魔鬼深坑”

这也是本文最干货的部分。真实的硬件产品体验，全是一个个极其隐蔽的“魔鬼细节”堆出来的：

### 🛑 坑 1：市面传统“长按死按说话”在生产力场景完全是灾难！
- **踩坑过程**：最初做语音输入，惯性思维做了类似微信对讲机的“按住屏幕说话，松手发送”。结果实际用了半天，大拇指痛得要命！跟 AI 提复杂的代码重构需求，经常要构思 15~30 秒，大拇指死死按在屏幕上不仅容易僵硬抽筋，稍微一滑就误触发了取消。
- **神级优化**：推翻重做，全面改为**点按开关制（Toggle 模式）**！
  - **轻点一下开麦**：波形亮起，进入倾听；
  - **双手彻底脱离**：你可以端着咖啡、靠在椅背上慢慢构思、从容说话，说两分钟也不累；
  - **随手轻点一下闭麦**：系统即刻智能识别落盘，伴随平滑倒计时，**全自动敲击 Enter 回车发送**！

---

### 🛑 坑 2：空闲状态点【取消】，整个电脑屏幕瞬间全选变蓝、光标乱跳！
- **踩坑过程**：在打磨取消逻辑时，为了保证取消录音能把输入法已经打到屏幕上的字删干净，我们在单片机里写了 `Ctrl+A` 紧接着 `Backspace`。但上线后发现一个要命的 Bug：当用户处于**空闲未录音状态**，如果手指不小心碰到了左下角的【取消】，单片机居然也下发了 `Ctrl+A`！这导致用户当前正在浏览的网页、文档或者代码全选变蓝，光标被瞬间移走，极度惊悚！
- **神级优化**：加入严苛的状态守护：
  ```cpp
  bool wasActive = state.isBleVoiceActive;
  bool wasPending = (state.pendingReturnTime > 0);
  // 核心守护：只有在正在录音或倒计时中才执行清空；
  // 空闲状态随便按取消，屏幕纹丝不动，绝对不跳光标！
  if (!wasActive && !wasPending) {
    setEmotion(EMOTION_IDLE, "未在录音", 600);
    renderScreen();
    return;
  }
  ```

---

### 🛑 坑 3：输入法落盘延迟导致的“残存废字”
- **踩坑过程**：国内主流输入法（百度、搜狗、微信输入法）在做语音转文字时，往往有 200~400ms 的网络与文字上屏延迟。如果用户点取消时只执行一次清空，往往清空完毕后，输入法最后几个字才刚刚打到屏幕上，导致屏幕上残留半截废字。
- **神级优化**：设计**两段式防残存扫尾机制**！
  - **第 1 阶段（650ms）**：充分留出输入法最后几个字上屏的时间，执行第一波扫除；
  - **第 2 阶段（450ms 后）**：自动触发二次终极扫尾，连扫两遍，彻底根除任何残存字！

---

### 🛑 坑 4：小屏幕滚轮容易误触系统快捷键
- **踩坑过程**：在做 Tab 2 屏幕滚轮时，向上滑动如果不小心划到了屏幕最顶沿，会误触屏幕顶栏的系统快捷键，直接跳出了当前页面。而且单纯的小滑块在大拇指滑动时很容易滑出界。
- **神级优化**：重构成**全高专属垂直电梯滑道**！
  - 右侧整条区域设为专属轨道；
  - **点按微调**：点滑道上方微调上滚、点下方微调下滚，滑块自动飞速跟随；
  - **长按电梯式连滚**：大拇指按住下方不放，像坐高速电梯一样连续平滑向下滚屏；
  - **顶栏绝对防误触**：严格限制滑道有效接触区，无论怎么划都绝对不碰顶栏！

---

### 🛑 坑 5：板载中文字库缺失，导致“下一页”按键显示成方框 □
- **踩坑过程**：在翻页卡片界面，上一页显示向上箭头 `▲`，而下一页居然显示成了一个“缺字方框” `□`！排查发现单片机内置的 `efontCN_14` 字体库中收录了 `▲` 编码，却偏偏漏掉了向下三角 `▼` 的字库编码，导致 M5GFX 渲染时 fallback 成了缺字方框。
- **神级优化**：彻底放弃字库字体依赖，改用**硬件原生矢量多边形绘制（`canvas.fillTriangle`）**：
  - 上箭头置顶、下箭头置顶；
  - 主文字居中对齐，中英双标规范化；
  - 100% 保证上下箭头锐利、饱满、绝对对称，彻底告别方框！

---

### 🛑 坑 6：为什么我们坚决不在主线固件里装载摄像头？
- **真实抉择**：CoreS3 自带了一颗 GC0308 摄像头，很多人第一反应是“把摄像头常开做人脸识别或隔空手势”。但我们实测发现：摄像头一旦常开，I2C/SPI 总线和 ESP32 算力会被吃掉大半，机身剧烈发热，电池掉电极快，更会严重拖慢按键和触控的轮询响应！
- **克制的产品哲学**：我们写好了完整的按需唤醒拍照驱动原型（`CoreS3Camera.h`，平时 100% 断电 0 功耗），但**坚决不装进主线出厂固件**！既然当前场景不需要，绝不为了凑功能而牺牲核心对讲与触控的顺畅度！

---

### 🛑 坑 7：Windows 后台黑框弹窗与串口互斥
- **踩坑过程**：电脑端的 Python 守护进程如果用普通的 `.bat` 启动，屏幕上会一直挂着一个丑陋的黑框 CMD 窗口，一不小心叉掉服务就停了；而且烧录固件时，如果 Python 进程正占着串口，烧录器就会报错 `Access Denied`。
- **神级优化**：
  - 编写了 VBScript 无黑框静默后台驻留工具（`scripts/install_startup.py`），加入 Windows 启动项，开机无感秒连；
  - 提供一键优雅停机与烧录时自动避让机制，插拔热重连毫不卡顿。
