# FlowDesk 0.5.0：Pico 逐键全拼与多输入法候选识别

本轮沿用 Windows + Pico 1（RP2040）的软件启停方案，增加逐键全拼输入与视觉候选词选字。软件、固件版本为 0.5.0，握手协议为 4；旧协议固件需重新烧录。

## 实现与适配范围

- 中文转全拼复用 `pinyin-pro@3.29.4`（MIT），词段划分使用 `Intl.Segmenter`；固件沿用 Pico SDK / TinyUSB。
- 主机每次只下发一个 ASCII 字符；Pico 发出键盘 HID 报告。模型读取当前候选页，软件按精确匹配候选的数字键选词，不固定选第一项。
- 按键之间有可取消的等待，中文词段完成后核对候选和已输入文字；中英文混排、常用标点、候选翻页及成功后的初始中英状态恢复已接入。逐键输入不使用剪贴板、粘贴或 Enter。
- 微软、微信、搜狗、百度是首批全拼适配目标。共同条件是 Shift 切中英、数字选候选、PageDown 翻页；自建窗口中的四种候选样式只证明模拟流程，不能替代这些输入法的实机验收。
- 必须从空白编辑框开始，候选页需完整显示在已选择的前台窗口内。双拼、五笔、emoji 和多行输入不在本轮范围。
- 失焦、候选不完整、输入内容不一致、取消或命令异常时停止，不在失败后盲按恢复键。持续回复保留 `uncertain` 和人工接管，界面提示检查发送记录、清理残留拼音/草稿；旧任务不自动重试。
- 自动模式的发送点击仍走所选执行器，并保留发送前会话、消息、全文核对。人工模式只生成待复制草稿。

## 验证环境

仅使用 Node 测试、真实渲染的自建虚构聊天窗口、虚拟串口、固定测试词库、虚构候选页、本机 HTTP 模型替身和 C fake HAL。IME 模型请求确实携带 fixture 的 PNG，替身根据 fixture 当前状态返回候选，不读取预期输出拼装候选。

未打开真实 COM、使用系统剪贴板、注入系统输入、调用真实模型或操作微信等真实账号。无实体开发板，不能把模拟通过描述为实物 HID、真实模型识别或客户验收通过。

## 本轮发现与处理

1. 初次集成发现固定虚构词库缺少 smoke 所用“自动”，输入按预期停止；补齐测试词库后完整 smoke 通过，保留无候选必须停止的生产校验。
2. 复核发现最大化窗口可能带有屏幕外不可见边框。IME 捕获改为复制目标窗口与虚拟桌面的交集，并保留完整窗口图像坐标；边框填充背景。纯 C# 测试覆盖负边框、多屏负坐标和完全离屏，不执行真实截图。
3. 五分钟测试首次出现批次回复数不一致，失败日志保存在 `artifacts/usb-soak-0.5-first-failed.log`。受控回归确认：两次稳定性观察之间到达新消息，会被普通扫描异常处理误转人工。现以 `TransientChatChange` 保留原检查点并延后到下一轮稳定扫描，不丢掉新消息；人工发出消息仍在下一轮转为人工接管。正常 incoming 和人工 outgoing 两条回归分别验证，不降低长测计数要求。

Node 回归现为 124/124 通过（`artifacts/tests-0.5.log`），包含实际 PowerShell helper 的编译、中文传输及纯截图交集计算，但不调用截图和输入操作。固件宿主测试与 RP2040 交叉编译均退出码 0，日志为 `artifacts/firmware-host-tests-0.5.log`、`artifacts/firmware-build-0.5.log`。Shift 使用 HID modifier 字节，Escape / PageDown 使用标准按键 usage；每个字符保留按下与释放确认。
