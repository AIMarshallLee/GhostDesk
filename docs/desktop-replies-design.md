# Windows 持续回复实现约定

本轮补齐真实 Windows 窗口的长时间监听和多会话回复。自动模式持续生成与发送，人工模式只生成待复制草稿。测试限定 FlowDesk 自有的虚构多会话桌面窗口，不接触微信及真实账号。

主进程持有可停止的轮询任务，串行切换窗口内的已配置会话。配置包括精确且唯一的会话备注名、窗口内的会话列表/标题/消息/输入/发送区域、知识库和工作流。首次观察建立基线，不回复历史消息。视觉服务通过客户配置的支持图片的 OpenAI 兼容接口识别窗口截图，操作复用现有 Windows PrintWindow/SendInput 驱动；模型不能输出任意系统命令。

每会话独立保存连续消息检查点和回复任务。新消息必须能与旧消息尾部连续对齐，无法证明连续性则交给人工。发送前再次验证会话、上下文、输入框及窗口身份，发送后仅在视觉确认出现对应发出消息时记为 visually_confirmed。这是界面观察，不是平台服务器送达回执。不明确的发送不得自动重试。

发送意图先持久化再输入。暂停、切换模式、人工接管和关闭取消旧工作；重启保留日志但暂停运行。焦点丢失、窗口关闭、锁屏、截图失败及持久化失败不得继续输入。全局同时仅一个桌面操作器运行。截图与密钥不进入日志或报告。

验收覆盖持续轮询、多会话隔离、相同文本重复消息、模型失败/超时、生成期间新消息、模式切换、失焦、未知发送结果、崩溃恢复及独立解压启动。真实模型质量与目标应用不同版本/缩放/多屏兼容性单独记录，不能用模拟结果冒充商业验收。
