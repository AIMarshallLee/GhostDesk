FlowDesk 0.7.0 — Windows 11 x64 + Pico USB 当前使用说明

系统要求：当前仅支持 Windows 11 x64（Intel / AMD 64 位）。Windows 7/8/8.1/10、Windows ARM64 和 Mac 暂不纳入支持范围。

本说明适用于 FlowDesk 0.7.0。Pico 固件仍为 0.5.0、协议仍为 4；已有匹配 0.5 UF2 的板无需为 0.7 软件更新重新烧录。Windows 11 x64 实机、客户输入法和另一台电脑仍待用户按下面步骤实测。

开始
1. 解压当前提供的 Windows 包后，从完整目录运行 FlowDesk.exe；不要只复制 EXE。
2. 先在“回复模式实验室”使用“测试规则（不调用 AI）”和虚构消息熟悉自动回复、人工复制回复与暂停。
3. 启动电脑操作、持续回复或审核后逐键填入前，必须连接 Pico 1（RP2040）和匹配的 0.5 UF2；自动与人工草稿模式都需要该硬件。USB 断开或异常会停止任务，不会改用 Windows 软件输入；离线时仍可查看管理和烧录说明。
4. 模型配置只在你明确开始后使用。先用内置虚构窗口和虚构内容验证，不选择真实账号窗口。

Pico 中文逐键输入
0.5 的 Pico 逐键输入路径不使用剪贴板、粘贴或 Enter。它把中文转成全拼，逐个发送 ASCII 键，再读取选中、前台目标窗口内的实际输入法候选页，按候选数字精确提交。

使用前准备：
- 启用全拼输入法；首批适配目标为微软、微信、搜狗、百度。界面中的四种样式和自建测试窗口只模拟外观，不代表这些品牌已经完成实机验收。
- Shift 应能在中文和英文间切换；数字键选择候选；PageDown 翻候选页。
- 从空白输入框开始，并最大化目标窗口，使输入法候选页完整位于该窗口边界内。截图只限已选择且在前台的窗口矩形。
- 本轮不支持 emoji、多行内容、双拼或五笔。

开始后，若焦点丢失、候选页不完整、视觉结果不确定或任务取消，软件立即停止，不会盲目切换输入法或尝试恢复。未提交的拼音和草稿保留在输入框中；人工清理后再重新开始。

电脑操作
1. 在“电脑操作”选择模型协议。Gemini 原生 Computer Use 使用 Gemini API Key，不是 Antigravity OAuth；它固定使用原生接口根地址。`gemini-3.8-flash` 为示例模型名，必须由你的 Gemini API 账户实际支持。既有 UI-TARS/豆包配置仍可继续使用。
2. 点击“打开内置测试窗口”，先使用虚构消息；人工复制模式只生成草稿，自动模式才会在确认后操作所选窗口。Gemini 提出需要确认的操作时，界面会展示原因和动作；确认、拒绝或停止前不能改设置或重启。
3. 使用 Pico 逐键输入时，Gemini 模式复用同一 Gemini API Key 的模型读取候选词，不另填普通视觉模型。开始前核对目标窗口、模型接口、截图和所选知识。运行中窗口失焦、标题或尺寸变化会停止后续操作。

桌面持续回复
1. 默认使用 Gemini 原生协议，并复用“电脑操作”页保存的 Gemini API Key；普通视觉模型协议仍兼容既有设置。选择明确的 Windows 窗口，完成会话列表、标题、消息、输入框、发送按钮五个区域校准。
2. 会话名必须准确且唯一。首轮只建立基线；自动模式仅处理确认的新消息，人工复制模式只产生草稿。
3. Pico USB HID 是启动持续回复的必要硬件；人工草稿模式也必须先连接。人工复制模式不会输入或发送回复。暂停、停止、断线、窗口变化或结果不确定时交人工，不自动重试。

Pico 烧录和自检
首次使用或固件不匹配时，按“Pico-到货烧录与测试.md”完成 BOOTSEL 烧录、端口选择、连接和自建测试输入区检查。已有匹配 0.5 固件时无需再次烧录。“一键识别”只识别可证明为 FlowDesk 的设备：唯一匹配时只读连接，不会启动 HID；多个匹配时请手动选择端口。连接本身不执行动作；软件中的开始、暂停和停止控制会话。

知识、流程与附件
1. “业务知识库”可从已审核问答整理知识或 SOP 候选；候选默认不参与回复，只有人工审核采纳后才生成并启用知识或流程。模型提炼会在发送选中问答前展示模型与接口并要求明确确认。
2. “附件助手”仅在你显式选择文件后分析并保存为任务草稿，不会自动读取聊天附件、发送消息或替代聊天窗口操作。

数据与反馈
API Key 仅保存在本机安全存储；使用模型时，所选窗口截图、指令及明确勾选的知识会发送到配置接口。反馈问题时记录 Windows 版本、显示缩放、输入法、失败步骤和页面提示；不要提交 API Key、真实聊天记录或私人截图。
