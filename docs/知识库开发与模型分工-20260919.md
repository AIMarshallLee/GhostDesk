# FlowDesk 知识库开发与模型分工

目标：用 5–7 天完成可验证的 Windows 11 + Pico 试用流程；客户知识库适配以 3–5 天为排期目标。3000–5000 元/年是拟定收费方案，尚不代表客户成交或盈利。

## 本轮范围与验收

1. Excel XLSX、Word DOCX、文本 PDF、CSV、JSON、TXT/Markdown、带角色聊天文本统一导入。采用现有开源解析器，不自行实现 Office/PDF 格式。扫描/加密/损坏文档必须明确报错或提示缺少文字。
2. 预览、编辑、来源位置、错误行、去重；提交只新增待审核且停用的知识，不覆盖现有工作区。
3. 批量审核启用，编辑内容后撤回审核；知识含问题、相似问法、标准答案、场景、标签和来源。
4. 离线检索演练及问题集评测，显示命中条目与来源，明确区分本地检索与模型生成。普通回复和持续回复共用同一检索逻辑。
5. 现有规则聊天整理按真实能力标注；预置模板先待审核，杜绝直接启用未经客户确认的业务承诺。
6. 使用虚构数据测试、构建并验证 Windows 包；不访问真实账号，不调用真实模型。实体板、真实模型和客户环境继续独立验收。

## 分工

| 任务 | 模型 | 边界 |
| --- | --- | --- |
| 范围、契约、服务集成及验收结论 | 当前主控 | 不重复已委托的仓库扫描 |
| GhostDesk 快速代码核查、复用判断 | Terra Medium | 已完成只读核查，保留既有 FlowDesk 底座 |
| XLSX/DOCX/PDF/文本解析与坏文件测试 | Terra Medium | 独立解析模块，不触碰模型或账号 |
| 导入审核与检索演练页面 | Terra Medium | 按共享契约实施，不改服务存储 |
| 客户模板、虚构问题集、适配说明 | Luna Medium | 资料与文档，避免高档模型重复执行 |
| 发布前关键问题复核 | Terra High | 聚焦错误启用、内容丢失、范围串用和接线 |
| 额外 Sol/Astra 子代理 | 本轮不预先安排 | 仅遇到明确难题再升级 |

## GhostDesk 核查结论

本地基线为 `169825c`，父提交 `3f857bd`；当前没有配置远端。已经包含同源桌面、固件、知识学习能力。现阶段不执行仓库迁移，也不把上游 README 的不可检测、全自动能力宣传当作验收证据。

本地新增 playbook 萃取采用规则拆分，原本可直接启用生成内容；这不能等同于经过客户确认的知识库。优先修正这条实际使用链路。上游近期 ESP32-S3 烧录与更多执行通道不纳入当前 Windows 11 + Pico 试用范围。

客户资料按每客户独立工作区部署。本轮不扩展 SaaS、多租户计费或 Mac。年度服务需另约定账号/电脑数、业务范围、适配条目与维护额度，API 和硬件费用单列。

## 本轮实际执行记录

- Luna Medium：完成虚构客户知识 CSV、10 问演练 CSV 和客户适配指南初稿。
- Terra Medium（复用 2 个执行代理）：完成解析/隔离 worker、UI、持续回复按消息检索、测试及许可证整理；按文件边界串行切换任务，避免重复扫描。
- 独立复核实际由 Terra Medium 执行：发现未审核检索参数和旧创建 API 绕过审核；主控已修复并回归。没有另建 Sol/Astra 子代理，也没有声称把主控模型切换成其他模型。
- 原计划中的 Terra High 保留为重大争议或跨模块未解问题的升级档。本轮问题均有小范围可复现用例，沿用现有 Terra 完成核验。
- 后续默认：模板/文档/单文件执行先用 Luna；2–3 模块业务逻辑用 Terra Medium；架构难题与重要验收才升级 Sol/Astra。每次先给清楚的文件所有权、验收条件和必要上下文，再启动子代理。
