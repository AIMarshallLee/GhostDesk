- 没有用户提供的模型凭证：真实供应商连通与识图质量未实测；服务测试使用受控假响应，不计作真实模型结果。

## 交付位置

- `release/FlowDesk-win32-x64/FlowDesk.exe`：解压目录内的 Windows 主程序，需与同目录运行库一起保留。
- `release/FlowDesk-win32-x64.zip`：便携分发包。
- `firmware/build/flowdesk_usb_bridge.uf2`：仅用于 Pico 1 / RP2040。
- `firmware/README.md`：购买型号、GPIO15 与 GND 接线、BOOTSEL 烧录与重建说明。
- `README.md`：所有页面、使用流程、开发与数据说明。

本版是视觉回复助手，支持人审后交接；不宣称具备无人值守微信运营、任意应用连续操作、保证账号不掉线等能力。Computer Use 项目核验与后续缺口见 [选型说明](Computer-Use选型.md)。

## 2026-09-14 网页双回复模式验收

用户最新限定只在自建网页工作台中，以虚构消息验证回复模式实验室。收到该限定后，Windows 客户端运行测试已暂停：`release/windows-software/FlowDesk-win32-x64/FlowDesk.exe` 是此前构建、尚未通过 smoke 的候选，不能作为已验收产品；根目录 `release/FlowDesk-win32-x64.zip` 是未包含新增双回复模式的旧版。

没有读取微信聊天、截取微信窗口、输入或发送微信消息。以下运行测试全部在本机网页进行，使用明确标注的规则回复；没有调用真实模型。

| 实际浏览器测试 | 结果 |
| --- | --- |
| 连续 3 条虚构消息 | PASS：3 个任务 sent，3 条模拟回复 |
| 三个模拟会话各 1 条 | PASS：lin、chen、zhou 各 1 条；独立页面及工作台内嵌页面均复测 |
| 相同消息 ID 重复提交 | PASS：1 个任务、1 条回复、重复计数 1 |
| 投递确认丢失 | PASS：出现 ack_lost 事件，仍仅 1 条回复 |
| 连续 3 次生成故障 | PASS：attempts=3、failed=1、0 条回复 |
| 延迟后暂停 | PASS：等待超过 700ms 后仍 queued，0 条回复 |
| 人工复制 | PASS：ready → copied，剪贴板内容与草稿一致，sent=0 |

测试中曾出现本地状态文件替换失败，页面显示 FAIL 并暂停。针对 Windows 短暂文件占用加入有上限的替换重试后，上述六项样例重新通过；持续保存失败仍应暂停，不能无限重试或伪报成功。另修复新样例运行时保留上一条 PASS 的显示问题。

最终源码检查：`npm test` 34/34 通过；`npm run build` 的 TypeScript 检查和网页生产构建通过。新增回归测试在三个会话入队且任务处于 generating 时注入两次 EPERM，验证恢复投递；持续 EBUSY 在五次尝试后暂停。桌面边界测试只执行纯函数，没有启动 Electron 或调用原生窗口接口。

最终模拟器处于暂停状态。入口：`http://127.0.0.1:5178/#autopilot`；独立页面：`http://127.0.0.1:5178/simulator.html`。这些证据验证本地消息流程，不证明真实供应商效果、微信兼容性、通用 Computer Use 或新版 Windows 包可用。
